# Frontend Portfolio (A4 / PDF)

프로젝트 스토리(문제 → 판단 → 결과)를 한 페이지에 담아, 바쁜 면접관이 **한 눈에** 읽고 질문할 수 있게 만든 포트폴리오 보일러플레이트입니다. 화면에서는 웹 문서처럼 보이고, 그대로 A4/PDF로 인쇄됩니다.

## 스택

Vite + React 18 + TypeScript · SCSS Modules(디자인 토큰은 CSS 변수) · ESLint + Prettier · 웹폰트 Pretendard(본문) / JetBrains Mono(데이터·태그·링크).

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입체크 + 프로덕션 빌드
npm run preview  # 빌드 결과 미리보기
```

## 내용 채우는 곳 (여기만 수정)

- `src/data/profile.ts` — 이름·소개·키워드·연락처. `showPhoto: true` 로 두고 `photoUrl` 지정 시 오른쪽 열에 사진 노출.
- `src/data/projects.ts` — 프로젝트 6개. `01`·`02`는 완성 예시, `03~06`은 빈 템플릿. **목차는 이 파일을 단일 출처로 자동 생성**됩니다.
- `src/data/organizations.ts` — 조직 태그 정의(라벨 + 색). 키를 추가해 `project.org` 에서 참조.
- 스키마 정의는 `src/types/portfolio.ts`.

## 주요 기능

- **커버 2단 레이아웃** — (좌) 이름·소개·키워드 / (우) 사진(옵션)·링크. 오른쪽 열 폭·간격은 `Cover.module.scss` 상단의 `--aside-w`, `--aside-gap` 로 조절.
- **목차 → 페이지 이동** — 목차 제목 클릭 시 해당 프로젝트로 부드럽게 스크롤.
- **조직 태그** — 목차와 프로젝트 헤더에 표시. 색은 `organizations.ts` 에서 태그별로 자유롭게 커스텀.
- **3막 상태 레일** — 문제(빨강) → 판단(파랑) → 결과(초록)를 세로 레일로 시각화.
- **요약 카드** — 세 막 어디에나 `cards` 로 핵심을 카드로 요약(막 색 상속).
- **하단 flow 띠** — `flow` 를 넣으면 문제→판단→결과를 연결한 카드 띠가 페이지 하단에 생겨, 카드만 봐도 핵심 파악 가능.
- **참고 링크(상단 고정)** — `github` / `npm` 은 URL만, `docs` 는 제목(label)까지 입력. 서비스별 테마(깃허브=검정, npm=빨강, docs=인디고) 자동 적용.

## PDF로 저장

우측 하단 **`PDF로 저장 / 인쇄`** 버튼(또는 `Cmd/Ctrl + P`) → 대상 "PDF로 저장", 여백 "없음", **배경 그래픽 켜기**.

## A4 넘침 감지

각 페이지는 정확히 210 × 297mm 고정. 297mm를 넘으면 해당 페이지 테두리가 **빨간색**이 되고 개발 콘솔에 몇 번째 페이지가 넘쳤는지 경고가 찍힙니다(`usePageGuard`). **한 페이지를 넘기지 않는 것**이 핵심 제약입니다.

## 글 작성 원칙

> 면접관은 바쁩니다. "이 사람이 어떤 문제를, 왜, 어떻게 풀었는가"가 3초 안에 읽히고, 그 위에서 질문이 나오게 만드는 것이 목표입니다.

### 1. 스토리라인은 항상 3막

| 막 | 필드 | 무엇을 쓰나 |
| --- | --- | --- |
| 문제 · 배경 | `problem` | **왜 이게 문제였는지** 상황과 비용을 구체적으로. 이 막이 납득되지 않으면 나머지가 무너집니다. |
| 고민 & 의사결정 | `decision` | **왜 그렇게 판단했는가.** 고려한 대안과 버린 이유까지. (트러블슈팅이면 증상 → 가설 → 검증) |
| 결과 | `result` | **두괄식으로 성과 먼저.** 정량은 `cards`(before → value). |

### 2. 각 막은 `lead` 한 줄 + `points` 2~4개 + (선택) `cards`

- `lead`: 그 한 줄만 읽어도 요지가 전달되는 두괄식 문장.
- `points`: 근거·디테일. 한 항목당 1~2줄. 길어지면 자릅니다.
- `cards`: 글로만 이어지면 읽기 어려운 부분을 카드로 요약. 각 카드 `{ label, value, before?, delta?, note? }`.

### 3. 하단 flow 로 한 번 더 요약

`flow` 에 문제/판단/결과를 각 한 줄로 적으면, 면접관은 그 세 카드만 따라가도 전체 스토리를 잡습니다. 본문을 다 읽지 않아도 되는 안전망입니다.

### 4. 기술은 최소, 판단은 최대

스택은 태그로만 짧게. 지면은 "무엇을 만들었나"보다 "왜 그렇게 결정했나"에 씁니다.

### 5. 참고 링크는 1~3개, 상단 고정

중요도 높은 것부터. `docs` 만 제목을 직접 붙일 수 있습니다(문서마다 제목이 다르므로).

## 구조

```
src/
├─ data/
│  ├─ profile.ts        # 개인 정보 (커버)
│  ├─ organizations.ts  # 조직 태그 정의(색 커스텀)
│  └─ projects.ts       # 프로젝트 6개 ← 주로 여기만 수정
├─ types/portfolio.ts   # 스키마 (스토리 구조를 강제)
├─ hooks/usePageGuard.ts# 297mm 초과 감지
├─ components/
│  ├─ Cover.tsx         # 1p: 개인정보(2단) + 목차(앵커)
│  ├─ ProjectPage.tsx   # 2p~: 프로젝트 1개 = 1페이지 (3막 레일 + 카드 + flow)
│  ├─ RefLinks.tsx      # 상단 참고 링크 (github/npm/docs 테마)
│  ├─ OrgTag.tsx        # 조직 태그
│  └─ PrintToolbar.tsx  # 인쇄 버튼 (화면 전용)
└─ styles/global.scss   # 디자인 토큰 · A4 지면 · 인쇄 규칙
```
